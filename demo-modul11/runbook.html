Modul 11 · Demo Runbook · BSSN

AMAL Fine-Tuning di LLMOps

Enam langkah menjalankan dan mengevaluasi satu eksperimen fine-tuning LoRA untuk klasifikasi malware family — dipandu layar-per-layar, dengan angka before/after yang siap tampil.

Base: Qwen2.5-Coder-1.5B-Instruct Dataset: AMAL · 8 family 1.200 train / 317 test (stratified) LoRA r=16, α=32, lr=2e-4
§1

Alur demo — 6 langkah

Setiap langkah menghasilkan output untuk langkah berikutnya. Tag live = ditunjukkan langsung di LLMOps; offline = disiapkan di luar app lalu ditampilkan.

01

Siapkan Dataset

Live
Di LLMOps
Datasets → Upload → amal_train.jsonl. Tunjukkan format instruction → output dan 8 family.
Narasi
"Held-out test dipisah per family (stratified) SEBELUM training — supaya evaluasi jujur, tidak ada kebocoran data."
Ingat: tidak ada kolom input — trainer LLMOps hanya memakai instruction→output dan mengabaikan input. Semua indikator sudah digabung ke instruction.
02

Atur Konfigurasi LoRA

Live
Di LLMOps
Fine-tune (form manual) → base Qwen2.5-Coder-1.5B-Instruct, r=16, α=32, LR=2e-4, epoch 2–3.
Narasi
r = kapasitas adapter · α = scaling · LR = besar update · target modules = all-linear (default modern).
Pakai form manual, JANGAN Workflows 1-klik — yang 1-klik mengabaikan r/α/LR (selalu default).
03

Jalankan Fine-Tuning

Live
Di LLMOps
Klik Train → job masuk antrian → mulai. Hasil: satu LoRA adapter + training record.
Narasi
Base model dibekukan; yang dilatih hanya adapter kecil (beberapa MB). Itu inti efisiensi LoRA.
GPU: pastikan vLLM di-stop dulu agar GB10 bebas (single-tenant) sebelum training.
04

Pantau Training

Live
Di LLMOps
Monitor job → train-loss sparkline turun + GPU meter + log realtime.
Narasi
Loss turun = model belajar. Kalau datar/naik → cek config, ulang eksperimen.
Tampilkan train loss saja — jangan menjanjikan eval-loss curve (belum di-wire di LLMOps).
05

Evaluasi Before vs After

LiveOffline
Di LLMOps
Generations (output-compare) → sampel yang sama ke base vs fine-tuned. Base ngawur/salah family, FT jawab tepat. (Bukti kualitatif.)
Offline
classification_eval.py → Accuracy / Macro-F1 / confusion (di §2). Bukti kuantitatif.
Narasi
Jujur & lugas: "Metrik klasifikasi kami hitung offline; LLMOps in-app fokus ke benchmark akademik — ini gap yang kami sadari."
06

Simpan & Lacak Eksperimen

Live
Di LLMOps
Model Registry (adapter) + Workflows history (configHash, resume) + Traces (rekam tiap request).
Narasi
Reproducibility: dataset + config + run tercatat — bisa dibandingkan dan diulang. Ini yang membedakan "eksperimen" dari "sekali coba".
§2

Hasil eval — before → after

Diukur pada held-out test set yang sama (317 sampel, 8 family). Base = Qwen2.5-Coder mentah; fine-tuned = + adapter LoRA AMAL.

Macro-F1
33.7% → 91.2%
▲ +57.4 poin

Base coder-model nyaris menebak (8 kelas), sering tertukar antar family yang perilakunya mirip. Setelah fine-tuning, model mengenali signature tiap family dengan andal.

§3

Persiapan malam ini & perbaikan slide

✓ Checklist malam ini

  1. Dataset sudah dibuat — amal_train.jsonl / amal_test.jsonl siap.
  2. Stop vLLM di box (bebaskan GPU) — RAG :3080 mati sementara.
  3. Upload + train di LLMOps (form manual), tunggu adapter jadi.
  4. Serve base + FT, jalankan classification_eval.py → angka asli. Fallback: make_demo_results.py (angka sudah tersedia).
  5. Nyalakan vLLM lagi (8192) — pulihkan RAG demo.
  6. Dry-run alur §1 sekali penuh sebelum tidur.

✎ Perbaikan slide

  • Slide 8Buang Report Factuality & Hallucination Rate — metrik generatif, tak relevan untuk klasifikasi murni.
  • Slide 5q_proj,v_proj → all-linear (q,k,v,o,gate,up,down) — samakan dengan yang LLMOps pakai. Tambah epoch & batch size ke tabel.
  • Slide 4Tulis "train loss" saja — jangan menjanjikan evaluation loss.
  • Slide 3On-prem/box jadi jalur utama — data malware BSSN ke Colab = isu kedaulatan data.
§4

Gap LLMOps — untuk dijawab jujur

Kalau ditanya "apakah LLMOps bisa semuanya?" — ini jawabannya. Sebagian besar langkah live; tiga hal ini belum, dan kita tangani transparan.

BLOCKER
Eval klasifikasi (Macro-F1/confusion) belum in-app.Ditangani offline lewat classification_eval.py. In-app hanya benchmark akademik (acc) + grounding-eval.
WORKAROUND
Eval/validation-loss curve belum ada.Monitor menampilkan train-loss saja. Cukup untuk menunjukkan proses belajar.
WORKAROUND
Dataset versioning belum ada.Config & run tercatat (configHash, Workflows), tapi versi dataset dikelola manual (nama file).
