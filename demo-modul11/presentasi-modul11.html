01

Dataset & Format Data

Apa yang kita ajarkan ke model, dan bagaimana bentuknya.

Dataset AMAL adalah kumpulan hasil analisis statis file PE (Windows executable). Setiap sampel memuat "sidik jari" file — imports (API yang dipanggil), sections + entropy, YARA matches, dan strings — tanpa pernah menjalankan file-nya. Tugas model: dari sidik jari itu, menentukan 1 dari 8 malware family.

Emotet loader TrickBot injector WannaCry ransomware Conficker worm AgentTesla keylogger Ryuk ransomware Zeus banker RedLine stealer
1.440baris training
360baris test (held-out)
8malware family
180 / 45per family (train / test)

Anatomi satu sampel — data asli

amal_train.jsonlTraining
# instruction (soal + fitur) Tentukan malware family dari fitur analisis statis PE berikut…
imports: GetUserNameA, GetLogicalDrives, mscoree.dll:_CorExeMain, VirtualAlloc sections: .text=7.13, .rdata=6.16, .data=5.09, .reloc=6.19 max_section_entropy: 7.13 yara_matches: DotNet_Obfuscation, Credential_Harvest, Browser_Data_Access strings: 'ntdll.dll', '\Wallets\'
output →RedLine
Cara baca: mscoree = program .NET, \Wallets\ + Browser_Data_Access = mencuri dompet & data browser → ciri RedLine (infostealer).
amal_test.jsonlHeld-out
# sampel yang TIDAK dilatih — # dipakai hanya untuk menilai
imports: CryptDecrypt, CreateProcessW, CreateRemoteThread, NtUnmapViewOfSection sections: .text=6.84, .rsrc=5.58, .rdata=5.45 max_section_entropy: 6.84 yara_matches: Process_Injection, Modular_Config strings: 'kernel32.dll', '\Windows\rundll32.exe'
output →TrickBot
Cara baca: CreateRemoteThread + NtUnmapViewOfSection + Process_Injection = teknik menyuntikkan kode ke proses lain → ciri TrickBot (injector).
Kenapa formatnya instruction → output?
Ini format SFT (Supervised Fine-Tuning): model belajar dari pasangan "kalau diberi soal ini → jawab ini". Cocok untuk klasifikasi karena ada satu jawaban benar. Fitur (sha256, imports, dst.) ditempel di dalam instruction karena trainer melatih pasangan instruksi→jawaban.

Format berbeda untuk metode training berbeda

Format hanyalah konvensi penamaan — intinya sama: memasangkan input dengan hasil yang diinginkan. Metode training menentukan bentuknya.

SFT
Meniru satu jawaban benar
{ "instruction": "…fitur PE…", "output": "RedLine" }
Untuk: klasifikasi, ekstraksi, ikut instruksi. ← yang kita pakai.
RL / Preferensi
Membandingkan dua jawaban (DPO)
{ "prompt": "Analisis file ini…", "chosen": "jawaban lebih baik", "rejected": "jawaban kurang baik" }
Untuk: memoles kualitas, gaya, keamanan — bukan menambah fakta.
TTS
Teks ↔ suara
{ "audio": "clip_0142.wav", "text": "teks yang diucapkan" }
Untuk: melatih model mengubah teks menjadi ucapan.
02

Konfigurasi LoRA

Parameter yang kita pilih — dan kenapa, dalam bahasa sederhana.
Analogi: fine-tuning LoRA itu seperti memberi karyawan berpengalaman (model dasar) sebuah buku catatan tempel berisi keahlian baru — tanpa menulis ulang seluruh isi kepalanya. Parameter di bawah mengatur seberapa tebal buku itu, seberapa kuat ia dipakai, dan seberapa cepat ia belajar.
ParameterNilaiArtinya (bahasa sederhana)
Base ModelQwen2.5-3BOtak dasar yang kita ajari — model yang sudah pintar bahasa, tinggal diberi keahlian khusus.
Epochs3Berapa kali model membaca seluruh dataset. 3× = cukup untuk hafal pola tanpa berlebihan. (default form = 1; kita naikkan ke 3.)
LoRA rank (r)16Ketebalan buku catatan — kapasitas adapter. Makin besar = makin banyak yang bisa dipelajari, tapi makin berat. 16 = pas untuk 8 kelas.
LoRA alpha (α)32Seberapa kuat catatan itu memengaruhi model (skala). Konvensi umum α = 2 × r → 32.
LoRA dropout0Persen koneksi yang sengaja "dilupakan" tiap langkah agar tak menghafal. 0 karena Unsloth paling cepat di 0 dan dataset sudah cukup bervariasi.
Learning rate2e-4Ukuran langkah tiap kali belajar. Terlalu besar → ngawur; terlalu kecil → lambat. 2e-4 = standar aman untuk LoRA.
Max steps-1Tidak dibatasi jumlah langkah — biarkan mengikuti epochs. (Angka positif akan menimpa epochs; -1 untuk latihan penuh.)
Max context length2048Panjang maksimal teks per sampel (token). Sampel kita pendek (~150 token), jadi 2048 sangat lega — tak ada yang terpotong.
Target modulesall-linearBagian model yang ditempeli adapter. Kita pakai semua lapisan linear = cakupan luas. (Versi minimal klasik: q_proj, v_proj.)

Prinsipnya: r = kapasitas, α = pengaruh, learning rate = kecepatan, epochs = pengulangan. Empat kenop ini yang paling menentukan hasil.

03

Metrik Evaluasi

Apa arti tiap angka — dengan hasil nyata AMAL v4.

Semua metrik dihitung di test set held-out (360 sampel yang tak pernah dilatih), memakai model yang sama persis untuk base & fine-tuned. Ini yang membuat perbandingannya jujur.

Accuracy

98,9%

Persentase tebakan benar dari total. 356 dari 360 benar. Kelemahan: bisa menipu kalau jumlah tiap kelas timpang.

Precision

makro 98,9%

Dari yang model bilang "X", berapa % benar-benar X. Menghukum salah tuduh (false positive).

Recall

makro 98,9%

Dari yang sebenarnya X, berapa % berhasil ditangkap. Menghukum yang terlewat (false negative).

Macro-F1

98,9%

Rata-rata keseimbangan Precision & Recall, tiap kelas berbobot sama. Metrik paling jujur untuk multi-kelas — ini angka utama kita.

Kenapa base cuma 7,5% Macro-F1 padahal Accuracy 18,1%?
Karena base menebak "WannaCry" untuk hampir semua sampel. Untuk WannaCry ia dapat recall 100% (semua tertangkap) tapi precision 22,6% (kebanyakan tebakan itu salah) — dan nol di kebanyakan kelas lain. Macro-F1 merata-rata semua kelas, jadi angka aslinya anjlok. Inilah kenapa Macro-F1 lebih jujur daripada Accuracy.
